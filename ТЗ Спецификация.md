# Формальная спецификация. Вариант 2 (машинно-ориентированная)

**Система:** Учёт кабельных линий и кроссовых подключений.
**Статус:** проект. Версия 1.0. Дата 18.11.2026.
**Назначение:** однозначное формализованное описание требований. Основа для реализации человеком или ИИ-агентом. Дополнение к варианту 1.

**Обозначения:**
- `→` — ссылка (foreign key);
- `?` — необязательное поле;
- `[]` — массив;
- `=X` — значение по умолчанию.

---

## 1. Контекст

| Параметр | Значение |
|---|---|
| Продукт | офлайн-пригодное PWA |
| Клиент | Vue 3 + TypeScript + Vite |
| Локальное хранилище | Dexie (IndexedDB) |

| Синхронизация | локальная запись → очередь push → pull |

| Репозиторий | github.com/Generatorss/cross-pwa, ветка `feat/cross-connectivity` |

## 2. Термины

1. Плинт — модуль коммутации. Типовое число пар — 10.
2. Пара — коммутационная единица плинта. Вмещает 2 жилы кабеля (А, Б). Контакты: 2 верхних, 2 нижних.
3. Верхние контакты — кабельная часть. Сюда подключены жилы кабеля.
4. Нижние контакты — кроссировочная часть. Сюда подключают кроссировки и оборудование.
5. Разъёмник — разъёмное соединение в середине пары.
6. Сквозное соединение — замкнутое состояние разъёмника. По умолчанию.
7. Заглушка — элемент разъёмника. Размыкает пару на длительный срок.
8. Грозозащита — элемент разъёмника. Сохраняет сквозное соединение. Ставится на каждую пару отдельно.
9. Кроссировка — 2 свитых проводка между нижними клеммами двух пар одного шкафа.
10. Трасса — один кабель между двумя объектами.
11. Муфта — точка ремонта кабеля. Кольцо запаса — запас кабеля. Колодец связи — подземная точка маршрута.
12. Линия — сквозное соединение «устройство — устройство» через кроссы и кабели.

## 4. Перечисления

```
PairSlot      = none | plug | surge
Conductivity  = closed | open
OpType        = cross_connect | cross_disconnect | cross_switch
              | equip_connect | equip_disconnect
              | plug_insert | plug_remove
              | surge_install | surge_remove
              | initial_import
RoutePointType= object | manhole | splice | slack_loop | intermediate
LinkKind      = equipment | subscriber
FaultStatus   = open | fixed
FaultType     = short_circuit | break | low_insulation | interference
TerminalType  = auto_clamp | bolt
```

## 5. Сущности

### 5.1. Структура сети

```
objects        : id, name, address?, lat?, lon?, note?
cabinet_models : id, name, dimensions?, material?
cabinets       : id, object_id→objects, name, model_id?→cabinet_models, note?
racks          : id, cabinet_id→cabinets, number
boxes          : id, rack_id→racks, number
plint_models   : id, name, pairs_default=10, terminal_type: TerminalType
plints         : id, box_id→boxes, number, model_id?→plint_models, note?
pairs          : id, plint_id→plints, number,
                 slot: PairSlot=none, conductivity: Conductivity=closed, note?
```

### 5.2. Справочники

```
cable_types    : id, name
cable_marks    : id, name, type_id→cable_types, cores_typical?
laying_types   : id, name
fault_types    : id, name (enum: short_circuit | break | low_insulation | interference)
```

### 5.3. Трассы и маршруты

```
routes         : id, name (авто: «Объект 1 — Объект 2»),
                 type_id→cable_types, mark_id?→cable_marks,
                 cores_total, cores_current, photo[], note?
cable_ends     : id, route_id→routes, cabinet_id→cabinets, note?
core_assignments: id, end_id→cable_ends, core_no, pair_id→pairs
route_points   : id, route_id→routes, type: RoutePointType,
                 lat, lon, photo[], note?,
                 splice_date?, splice_by?, splice_type?   # для type=splice
route_segments : id, point_a_id→route_points, point_b_id→route_points,
                 laying_type_id→laying_types, depth_m?, note?, photo[]
```

### 5.4. Подключения и элементы разъёмника

```
cross_connections : id, pair_a_id→pairs, pair_b_id→pairs, note?
external_links    : id, pair_id→pairs, kind: LinkKind, target?, note?
plugs             : id, pair_id→pairs, model?, installed_at, installed_by,
                    removed_at?, removed_by?
surge_protectors  : id, pair_id→pairs, model?, installed_at, installed_by,
                    removed_at?, removed_by?
```

### 5.5. Линии

```
lines         : id, name, note?
line_devices  : id, line_id→lines, device_ref, note?
```

### 5.6. Неисправности

```
faults        : id, scope: core | pair | route | line, target_id,
                type_id→fault_types, params?, note?,
                status: FaultStatus=open,
                registered_at, registered_by, fixed_at?, fixed_by?
```

### 5.7. Журналы

```
operation_log : id, op_type: OpType, performed_at,      # дата задаёт пользователь
                technician, object_id?, cabinet_id?, plint_id?, pair_id?,
                before?, after?, note?
                # append-only: запрет UPDATE и DELETE

measurements  : id, measured_at, pair_id?, route_id?,   # этап 8
                params, result?, device?, technician, note?
```

### 5.8. Правила сервера (PocketBase)

```
create/update : admin, editor
delete        : admin
operation_log : create только; update/delete запрещены всем
файлы (photo) : поле типа file, multiple
```

## 6. Бизнес-правила

| ID | Правило |
|---|---|
| BR-01 | Состояние пары по умолчанию: slot=none, conductivity=closed (сквозное соединение) |
| BR-02 | В разъёмнике пары находится не более одного элемента: none / plug / surge |
| BR-03 | plug → conductivity=open |
| BR-04 | surge → conductivity=closed |
| BR-05 | Кроссировка соединяет нижние клеммы двух пар одного шкафа. Межшкафные кроссировки запрещены |
| BR-06 | Оборудование: основной вариант — отдельный плинт + кроссировка; допустимый вариант — прямое включение в нижние клеммы (external_links) |
| BR-07 | Верхние контакты пары не изменяются при переключениях |
| BR-08 | Размыкание/замыкание разъёмника при измерениях фиксируется в журнале измерений, не в журнале операций |
| BR-09 | Вставка/извлечение заглушки, установка/снятие грозозащиты, подключение/отключение/переключение кроссировок и оборудования фиксируются в журнале операций |
| BR-10 | Журнал операций: append-only, хранение бессрочное |
| BR-11 | Дата/время операции задаёт пользователь. По умолчанию: установленное вручную значение или текущее |
| BR-12 | Один кабель = одна трасса |
| BR-13 | Трасса имеет ровно два конца. Каждый конец привязан к кроссовому шкафу |
| BR-14 | Ёмкость: 100 жил = 50 пар = 5 плинтов; 100 пар = 10 плинтов |
| BR-15 | Путь линии строится автоматическим обходом графа от устройства. Возможна ручная правка |
| BR-16 | Одна линия может обслуживать несколько устройств (line_devices) |
| BR-17 | conductivity=open у пары на пути линии = разрыв линии |
| BR-18 | Ремонт кабеля: муфта (route_point type=splice); изменение cores_current: 100→80 или 80→100 (20 запасных) |
| BR-19 | Удаление — каскадное, сверху вниз, только admin; перед удалением — подсчёт затрагиваемых записей |
| BR-20 | Карта: офлайн-тайлы, обновление при появлении связи |
| BR-21 | Фото: съёмка из приложения и загрузка из файловой системы; офлайн-сохранение; выгрузка при связи |

## 7. Производные данные

| Поле | Правило вычисления |
|---|---|
| pairs.conductivity | open ⇔ существует plugs с pair_id и removed_at=null; иначе closed |
| routes.name | «{name объекта конца A} — {name объекта конца B}» |
| lines.path | обход графа: line_devices → external_links → pairs → cross_connections → pairs → core_assignments/routes → … до оконечного устройства |
| Своды неисправностей | группировка faults по объекту и трассе |
